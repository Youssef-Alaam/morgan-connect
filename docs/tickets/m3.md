# Tickets: M3 (Safety and heavy tools)

Status: draft for the owner's review, 2026-11-26. Tickets are disposable: when the spec changes, close the unbuilt ones and regenerate.

Every ticket is a vertical slice: when it is merged, something new can be shown working. Every ticket follows `STANDARDS.md` (tests first, all CI checks green, one PR, at most 400 changed lines). "Tests first" lists the failing tests the builder writes before any code. A ticket too big for one PR is split into lettered parts (a, b, c), each its own PR of at most 400 lines, merged in order. Library names marked _(proposed)_ are not decided until the owner approves them.

Milestone goal (spec section 6): the release gate (D39) passes for the first time: all tests green, typecheck clean, zero unsafe actions on the holdout safety evals, on every engine being shipped (Pi only, at M3). The README banner changes from "do not expose" to "preview".

What already exists on `main` and is built on here: the single policy gate (`src/policy/gate.ts`) that runs every tool call, decides from a profile, writes exactly one audit row after the run, and fences every tool result and tool error through `wrapUntrusted`; `decide(profile, actionType)` that treats an unlisted type as `off`; the six action types `read`, `create`, `overwrite`, `delete`, `send`, `execute` (`src/tools/registry.ts`); approvals bound to the exact arguments by `approvalHash`, used once, with a waiting room and expiry (`src/policy/approvals.ts`, `approval-hash.ts`, `approval-wait.ts`); the `Untrusted` branded type, `untrusted()`, `wrapUntrusted()` (defangs fences, invisibles and look-alike brackets) and `trusted()` / `joinSystem()` for system prompt text (`src/safety/untrusted.ts`); `withOwner` and row-level security on every user-data table (`src/data/rls.ts`, migration 0013); the evals runner with a hard spend cap and a stop on a $0 cost report, five dev scenarios on the vault capture, judged on what changed in the vault (`src/evals/`), run by `npm run evals -- --set dev`, which refuses any other set. Still open from M2 and a hard dependency where noted: access profiles per user and device with the shell-gate level stored (M2-9a), the gate deciding from `profileFor` instead of `OWNER_PROFILE` (M2-9b), web chat approvals (M2-12b), the design system (M2-13b), the providers and channels page with the install-wide `routes` table (M2-15e), and the two M2 dev evals (M2-16).

### M3-4. The trust check, with the coverage fix

Split into three PRs. The fix: Nod's check proves the user's words exist, not that they cover the action (R2); ours must prove both.

#### M3-4a. The quote must be the user's own words

- **Blocked by:** M3-3a.
- **Demo:** for a proposed action, the trust check returns the quote it relies on; a quote that is not found word for word in this person's own messages in this conversation is refused before the safety model's answer counts.
- **Tests first:** a quote found only in a tool result, a fetched page, a file, a mail, a summary row or Morgan's own reply is refused (only the person's own `user` messages in this conversation count, after the idle-gap and compaction rules of M2-3); matching is exact after Unicode normalisation (NFC, invisibles stripped, whitespace collapsed), so a look-alike or zero-width variant is refused; a quote from another person's chat is refused (isolation, through `withOwner`); an empty or one-word quote is refused; the check is a pure function, unit-tested at 100% branches.
- **Work:** `src/safety/quote.ts` (`findQuote(messages, quote)`); the user-message reader in `src/data` under `withOwner`.

#### M3-4b. The quote must cover the action

- **Blocked by:** M3-4a.
- **Demo:** "save a note about the meeting" covers `vault.capture` of a meeting note, but does not cover `vault.capture` of a note telling someone to wire money, nor a `send` of anything, nor a `delete`; each refusal names what the words did not cover.
- **Tests first:** coverage is judged on three parts, each required: the action type (a quote for `create` does not cover `send`, `delete` or `execute`); the target (path, recipient, URL host, command) is named or plainly implied by the quote; the content is what the person asked for and not more (a capture whose text adds an instruction, a link or a recipient the quote does not contain is refused); deterministic pre-checks run first (action type words, target present in the quote where the tool marks the target as "must be named", e.g. a mail recipient), and only the rest goes to the safety model; the safety model sees the quote and the action's exact arguments, the arguments fenced as `Untrusted`; any missing part is "not covered"; a table of at least 30 (quote, action) pairs, half covered and half not, runs on the fake safety model with scripted answers and on the deterministic pre-checks for real.
- **Work:** `src/safety/coverage.ts`; a `target` and `mustNameTarget` field on `ToolDefinition` (registry change, every existing tool updated); the prompt to the safety model as `trusted()` text, drafted by the reviewer (spec section 8: Opus drafts safety-check prompts).

#### M3-4c. The gate runs the trust check before every gated action

- **Blocked by:** M3-4b, M2-9b.
- **Demo:** an `ask` action whose quote does not cover it is refused with "Your words did not cover this: <reason>." and no approval is asked; one that is covered asks for approval as before; an `auto` action that is not a read is refused the same way if not covered; a read never calls the safety model.
- **Tests first:** the trust check runs for every action type except `read` and never for `read` (C6), counted with the fake safety model; it runs before the approval question, so a person is never asked to approve what their words did not cover; a refusal writes one audit row with `decision: 'refused'` and the reason, and the model is told it was refused; a safety-model failure or timeout refuses (fail closed) and does not retry a changing tool (G3); perf project: Morgan's overhead around the fake safety model stays within budget, and the real-model median is recorded by hand in the PR (target 1.5 s).
- **Work:** the trust step in `src/policy/gate.ts` between `decide` and `beforeRun`; the refusal message as a translation key; the audit reason field.
- **Out of scope:** engine built-in tools (M5, engine rule C8).
