# Tickets: M7 (Remaining engines, 1.1)

Status: draft for the owner's review, 2026-11-28. Tickets are disposable: when the spec changes, close the unbuilt ones and regenerate.

Every ticket is a vertical slice: when it is merged, something new can be shown working. Every ticket follows `STANDARDS.md` (tests first, all CI checks green, one PR, at most 400 changed lines). "Tests first" lists the failing tests the builder writes before any code. A ticket too big for one PR is split into lettered parts (a, b, c), each its own PR of at most 400 lines, merged in order. Library names marked _(proposed)_ are not decided until the owner approves them.

Milestone goal (spec section 6): Google's SDK on a Gemini key, the Copilot SDK, the Cursor SDK and ChatGPT sign-in, each under the engine rule (C8) and after its route is re-verified (G11, A12). No separate "done when" is written in the spec; these tickets use the engine rule's own test: the holdout safety evals pass on each engine shipped, and an engine that cannot be gated ships chat-only or not at all.

What already exists and is built on here (from M5): the engine port with Pi, HTTP and the Claude Agent SDK adapters, the pre-tool hook pattern, optional dependencies behind the `pi-only` job, the release gate over a list of engines, provider profiles with tiers. Spec section 10 checks that block parts of this milestone: whether the Copilot and Cursor SDKs let us intercept or disable every built-in tool (first result, `research/sdk-tool-interception.md`: Copilot open until its sub-agent hole is tested; Cursor fails today except as text-only); how an app qualifies for "Sign in with ChatGPT" and whether Pi's login is that flow (`research/chatgpt-sign-in.md`, unverified); the licences of the Copilot and Cursor SDKs.

## M7. Remaining engines

### M7-1. Google's SDK on a Gemini API key

#### M7-1a. The adapter, with our tools only

- **Blocked by:** nothing in M7.
- **Demo:** with `ENGINE=gemini` and a person's or the admin's Gemini key, the owner chats and "capture this" asks for approval as on Pi.
- **Tests first:** the adapter passes the engine contract test on recorded fixtures; only our registry's tools are offered as function declarations, and the SDK has no built-in tools switched on (code execution, search grounding off, asserted); usage reaches the ledger; the Gemini API-key route is a row in the policy file, re-verified in the PR with source and date, and a free-tier key is labelled with Google's data-use note (_proposed_, doubt 2); the package is optional and the `pi-only` job still passes.
- **Work:** `src/providers/gemini/`; the route row; tier entries in the provider profile.

#### M7-1b. Safety evals on Gemini

- **Blocked by:** M7-1a.
- **Demo:** the release gate runs the holdout set on Gemini and prints its table.
- **Tests first:** `gemini` joins the gate's engine list only when its package is installed; a single unsafe action fails it.
- **Work:** the engine entry; any engine-specific prompt fix goes through the dev set, never the holdout.

### M7-2. The Copilot SDK, per person's own GitHub sign-in

#### M7-2a. The interception test

- **Blocked by:** the licence check of the Copilot SDK.
- **Demo:** a test harness shows, for every tool the Copilot SDK can call (including through a sub-agent), that our hook sees the call before it runs and can deny it; the result is written to `docs/research/sdk-tool-interception.md`.
- **Tests first:** a recorded or sandboxed run per built-in tool kind (file, shell, network, sub-agent); any tool our hook cannot see is listed as a hole.
- **Work:** the harness under `test/`; the research note updated. If a hole remains, M7-2b ships the engine chat-only (C8).

#### M7-2b. The adapter and the person's own sign-in

- **Blocked by:** M7-2a.
- **Demo:** a person signs in with their own GitHub account through the Copilot SDK's flow and chats on their own Copilot plan; nobody else can use that sign-in.
- **Tests first:** the token is sealed in the person's credential vault and never used for another person (D15); usage is recorded but not counted against the admin-key budget (D46); every tool call passes the gate, or all tools are off if M7-2a found a hole; the route row is re-verified in the PR.
- **Work:** `src/providers/copilot/`; the sign-in screen; the route row.

#### M7-2c. Safety evals on Copilot

- **Blocked by:** M7-2b.
- **Demo and tests:** as M7-1b, for `copilot`. The eval run needs a Copilot seat (doubt 3).
- **Work:** the engine entry.

### M7-3. The Cursor SDK

## Doubts for the owner

1. **No "done when" in the spec for M7.** The tickets use the engine rule and the release gate as the test. Say if a different bar is wanted.
2. **Gemini free-tier keys** train on data (Google's terms). M7-1a proposes labelling such a key on the providers page rather than refusing it.
3. **Eval seats.** Running holdout evals on Copilot and Cursor needs a seat on each plan; who pays and whose account is the owner's call.
4. **Licences of closed SDKs** need the same exception as the Claude Agent SDK (M5 doubt 1).
5. **ChatGPT sign-in may end as "no legal route"** for server installs; M7-4b handles all three outcomes.
